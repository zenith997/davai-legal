1. Introduction and Acceptance

This Privacy Policy ("Policy") governs the collection, use, storage, and disclosure of information in connection with DavAI (the "Application"), a medication reminder and adherence-tracking application — covering any prescription across any medical specialty — developed and maintained by Arsh Duggal (the "Developer"). By downloading, installing, or using the Application, you ("User," "you") acknowledge that you have read, understood, and agree to be bound by this Policy. If you do not agree with any part of this Policy, you should not use the Application.

2. Definitions

  • "Application" means the DavAI mobile software application, in any version, distributed via the Apple App Store or Google Play Store.
  • "Personal Data" means any information relating to an identified or identifiable natural person.
  • "Profile" means a named person tracked within the Application on a given Device — either the Device owner ("Self Profile") or someone a User is caring for ("Dependent Profile"), as described in Section 7.
  • "Local Storage" means data storage located solely on the User's own Device, not transmitted to or accessible by the Developer.
  • "Third-Party Service Provider" means an independent third-party organization engaged to process specific data on the Developer's behalf, as further described in Section 6.
  • "Device" means the smartphone, tablet, or other hardware on which the Application is installed.

4. How We Use Information

Information described in Section 3 is used exclusively for the following purposes:

  • To display and personalize the Application interface for each profile on the Device;
  • To generate, schedule, and deliver medication reminder notifications;
  • To calculate and display adherence statistics, including completion percentage and streaks;
  • To detect and log a missed dose for a Dependent Profile, and to alert the User on this Device, as described in Section 7;
  • To extract structured medication information from a prescription photograph submitted by the User, via the Third-Party Service Provider described in Section 6.

Information is not used for advertising, is not sold, and is not used to build behavioral or marketing profiles.

5. Legal Basis for Processing

Where applicable data protection law requires a legal basis for processing, the Developer relies on: (a) the User's consent, obtained via the in-application acceptance step prior to profile setup and prior to any use of the prescription-scanning feature; and (b) legitimate interest in operating the core reminder, tracking, and guardian-alert functionality of the Application, which is limited to on-device processing as described in Section 8. Consent for prescription-photo processing may be withdrawn at any time by declining to use the "Scan Prescription" feature; withdrawal does not affect the lawfulness of processing carried out prior to withdrawal.

6. Third-Party Service Providers and Disclosure

When the User submits a prescription photograph via the "Scan Prescription" feature, that image is sent from the User's Device to a relay service the Developer operates (a serverless function hosted on Cloudflare, Inc.), which forwards it to OpenAI, L.L.C. ("OpenAI") for the sole purpose of extracting structured medication data (name, form, dosage, frequency, and duration), and returns that structured result to the Application. The Developer's relay does not persist, log, or retain the photograph or the extracted data — it exists only to keep the Developer's OpenAI credentials off the User's Device, and the image passes through it transiently, in memory, for the duration of a single request.

This transmission constitutes the entirety of data disclosed by the Application to any third party. Per OpenAI's published API data usage terms, data submitted through the API is not used to train OpenAI's models by default, and is subject to OpenAI's own Privacy Policy, which governs OpenAI's independent processing of that data as a separate data controller for its own retention and security practices. Cloudflare processes the transient request as the Developer's infrastructure provider and is subject to Cloudflare's Privacy Policy in that capacity. No API key or credential of any kind is stored on, or ever visible from, the User's Device. Users who wish to minimize the information contained in a submitted photograph may crop or redact portions of a document not necessary for medication extraction (e.g., full addresses or identification numbers) prior to submission.

Other than the disclosure described in this Section, the Developer does not sell, rent, lease, or otherwise disclose Personal Data to any advertiser, data broker, analytics provider, or other third party. The Developer's only server-side component is the transient scan relay described above, which does not store User data; accordingly, no Personal Data is disclosed in connection with a merger, acquisition, or asset transfer, as none is held by the Developer to transfer.

7. Guardian and Dependent Profiles

The Application lets a User add more than one Profile on their Device: their own ("Self Profile"), and one or more people they are caring for ("Dependent Profiles"). This is a same-device feature — as of this version, DavAI does not synchronize data between two different Devices. A User acting as a guardian enters and manages a Dependent Profile's medications directly on their own Device; that Device is what receives reminders and missed-dose alerts for that Dependent Profile, because it is the Device on which that data is entered and stored.

A pairing code is generated for each Self Profile and required when creating a Dependent Profile, so a guardian must have actually obtained that code from the person they're adding rather than skipping the step. At present, entering that code does not establish a live connection to the other person's own Device or Application instance — no data is transmitted between Devices as a result. The code is checked only for well-formed format on the guardian's Device and stored locally as a label; it is reserved for a future version of the Application that may add real-time cross-device sync, at which point it would be validated against the other Device. If introduced, that capability will be described in an updated version of this Policy before it is enabled.

A missed-dose alert (Section 4) for a Dependent Profile is generated and delivered entirely on the guardian's own Device, using that Device's local notification system, and is logged in the Application's Guardian tab on that same Device. No missed-dose data is transmitted to the Developer or to any third party.

8. Data Storage, Retention, and Deletion

With the exception of the transient disclosure described in Section 6, all Personal Data described in Section 3 is held in Local Storage on the User's Device only, using the standard application-storage mechanisms provided by the Device's operating system (iOS or Android). This includes data for every Profile on the Device, including Dependent Profiles. Other than the transient scan relay described in Section 6 — which processes a submitted photograph in memory for a single request and retains nothing afterward — the Developer does not operate, and this Application does not transmit data to, any centralized database, cloud-storage service, or backend server under the Developer's control.

Data is retained in Local Storage for as long as the Application remains installed on the Device, or until the User deletes a specific Profile or record within the Application. Removing a Profile deletes that Profile's medications, reminders, and any related missed-dose log entries from the Device. Uninstalling the Application permanently and irretrievably deletes all associated Local Storage data in accordance with the Device operating system's standard app-removal behavior. Because the Developer does not retain a separate copy of this data, the Developer has no ability to recover data deleted in this manner, and no residual copy is retained by the Developer following uninstallation.

9. Data Security

The Application relies on the security architecture provided by the underlying mobile operating system (iOS or Android) to protect Local Storage, including operating-system-level application sandboxing that prevents other applications from accessing the Application's stored data without authorization. Transmission of a prescription photograph to the Third-Party Service Provider described in Section 6 occurs over an encrypted (HTTPS/TLS) connection. While the Developer takes commercially reasonable steps consistent with these platform protections, no method of electronic storage or transmission is completely secure, and the Developer cannot guarantee absolute security.
