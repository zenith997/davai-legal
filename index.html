If you do not agree with any part of this Policy, you should not use the Application.

  • "Personal Data" means any information relating to an identified or identifiable natural person.

  • "Local Storage" means data storage located solely on the User's own Device, not transmitted to or accessible by the Developer.
  • "Third-Party Service Provider" means an independent third-party organization engaged to process specific data on the Developer's behalf, as further described in Section 6.
  • "Device" means the smartphone, tablet, or other hardware on which the Application is installed.

4. How We Use Information

Information described in Section 3 is used exclusively for the following purposes:

  • To display and personalize the Application interface for each profile on the Device;
  • To generate, schedule, and deliver medication reminder notifications;
  • To calculate and display adherence statistics, including completion percentage and streaks;
  • To detect and log a missed dose for a Dependent Profile, and to alert the User on this Device, as described in Section 7;
  • To extract structured medication information from a prescription photograph submitted by the User, via the Third-Party Service Provider described in Section 6.

Information is not used for advertising, is not sold, and is not used to build behavioral or marketing profiles.

6. Third-Party Service Providers and Disclosure

When the User submits a prescription photograph via the "Scan Prescription" feature, that image is sent from the User's Device to a relay service the Developer operates (a serverless function hosted on Cloudflare, Inc.), which forwards it to OpenAI, L.L.C. ("OpenAI") for the sole purpose of extracting structured medication data (name, form, dosage, frequency, and duration), and returns that structured result to the Application. The Developer's relay does not persist, log, or retain the photograph or the extracted data — it exists only to keep the Developer's OpenAI credentials off the User's Device, and the image passes through it transiently, in memory, for the duration of a single request.

This transmission constitutes the entirety of data disclosed by the Application to any third party. Per OpenAI's published API data usage terms, data submitted through the API is not used to train OpenAI's models by default, and is subject to OpenAI's own Privacy Policy, which governs OpenAI's independent processing of that data as a separate data controller for its own retention and security practices. Cloudflare processes the transient request as the Developer's infrastructure provider and is subject to Cloudflare's Privacy Policy in that capacity. No API key or credential of any kind is stored on, or ever visible from, the User's Device. Users who wish to minimize the information contained in a submitted photograph may crop or redact portions of a document not necessary for medication extraction (e.g., full addresses or identification numbers) prior to submission.

Other than the disclosure described in this Section, and the guardian cross-device sync described in Section 7 (which also runs on Cloudflare infrastructure, but persists data rather than processing it transiently), the Developer does not sell, rent, lease, or otherwise disclose Personal Data to any advertiser, data broker, analytics provider, or other third party.

7. Guardian and Dependent Profiles

The Application lets a User set up their own Profile ("Self Profile") and, separately, lets another User on a different Device link as a guardian to watch that Self Profile — for example, an adult child watching a parent's medication schedule from their own phone. This is a cross-device feature: a Self Profile's current medication list and daily dose-taken status are synced to a server the Developer operates (a Cloudflare Workers application with a Cloudflare D1 database, both provided by Cloudflare, Inc.), so that a linked guardian's Device can display a live, read-only copy and receive a push notification if a dose goes 30 or more minutes unmarked past its scheduled time.

A pairing code is generated for each Self Profile. A guardian must enter that code — obtained directly from the person they're caring for — to link their Device; the code is validated against the Developer's server before linking succeeds. Once linked, the Self Profile's Device automatically syncs its current medication list (medicine name, dosage form, frequency, instructions, duration, and today's dose-taken status) to the server on every change. This synced copy does not include the User's name beyond what was entered for the Profile, adherence history, or any data from other Profiles on the same Device. A guardian's view is read-only: the Application does not allow a guardian to edit, delete, or mark doses taken on someone else's Profile.

To deliver a missed-dose push notification, a guardian's Device registers an Apple-issued push notification token with the Developer's server, associated only with the pairing code they're watching. The server checks, on a recurring automated schedule, whether any watched Profile has a dose that has gone unmarked 30 or more minutes past its scheduled time; if so, it sends a notification directly to Apple's Push Notification service, which delivers it to the guardian's Device. This check-and-alert log (which profile, medicine, and date — not the medication list itself) is retained on the server so the guardian's Application can display a short history of past alerts.

A User may remove a guardian link (or a Self Profile may stop syncing) at any time by removing the relevant Profile within the Application, which deletes that Profile's synced data and any registered push token from the Developer's server. A User who never sets up or is never linked to a guardian relationship has no data described in this Section transmitted to or stored on the Developer's server.

8. Data Storage, Retention, and Deletion

The full Personal Data described in Section 3 — every Profile's complete medication records, adherence history, and settings — is held in Local Storage on the User's Device only, using the standard application-storage mechanisms provided by the Device's operating system (iOS or Android). The Developer does not operate, and this Application does not transmit data to, any centralized database for that full dataset.

The exception is the narrower guardian-sync dataset described in Section 7: for a Self Profile that has at least one linked guardian, a reduced copy (current medication list and today's dose-taken status only — not adherence history, and not data from any other Profile on the Device) is stored in a Cloudflare D1 database the Developer operates, along with any guardian push notification tokens and a log of past missed-dose alerts for that Profile. This copy persists on the server for as long as the guardian link remains active, is overwritten on every sync (not accumulated as a history), and is deleted from the server when the Profile or the guardian link is removed within the Application, as described in Section 7.

Data held in Local Storage is retained for as long as the Application remains installed on the Device, or until the User deletes a specific Profile or record within the Application. Removing a Profile deletes that Profile's medications, reminders, and any related missed-dose log entries from the Device, and (where applicable) its synced copy and push token from the Developer's server. Uninstalling the Application permanently and irretrievably deletes all associated Local Storage data in accordance with the Device operating system's standard app-removal behavior; because a push token tied to the uninstalled Device also stops functioning, no further guardian alerts are sent for Profiles it was linked to, though the last-synced server-side copy may persist until separately removed or naturally superseded.

9. Data Security

The Application relies on the security architecture provided by the underlying mobile operating system (iOS or Android) to protect Local Storage, including operating-system-level application sandboxing that prevents other applications from accessing the Application's stored data without authorization. Transmission of a prescription photograph to the Third-Party Service Provider described in Section 6 occurs over an encrypted (HTTPS/TLS) connection. While the Developer takes commercially reasonable steps consistent with these platform protections, no method of electronic storage or transmission is completely secure, and the Developer cannot guarantee absolute security.
